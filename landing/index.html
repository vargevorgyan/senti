Server gateway — Support role

Support agents can read tickets and customer names, never card numbers or payments. They may reply to tickets but not delete them.

  • allow read tickets.*
  • allow read customers.name
  • block read customers.card_number
  • block any access to payments
  • allow insert ticket_replies
  • supervisor anything else

On your server, agents never get the keys.

Claude Code, Cursor or your own support bot reach the server’s files, database and commands only through Senti’s MCP gateway. Senti holds the access, checks every call and does the work itself.

    Let the dog in.

    Set it up once for the whole company. Your admin runs one command on a server; everyone else joins with the one line from their invite, and every supported agent they use (Claude Code, Codex, Cursor, Cline and more) is protected from then on.

    # 1. On your server: admin panel, company AI, MCP gateway
git clone https://github.com/vargevorgyan/senti && cd senti
./senti-server

# 2. Each developer’s Mac: the line from their invite (no admin password)
curl -fsSL https://senti.your.co/install.sh | sh -s -- '<invite link>'

# 3. Bots and agents on the server gateway
claude mcp add --transport http senti-server \
  https://senti.your.co/api/v1/mcp/ --header "Authorization: Bearer sag_…"

    It asks a few questions, starts the admin panel and prints its address. Invite people there: each person gets a link with their one-line setup. Developers’ computers need macOS for now. To join from outside the office, give the server an address people can reach (--public-url).

    Just you, no company? On an Apple Silicon Mac, in a clone of the repo: cd engine && uv sync --extra mlx && uv run senti start && uv run senti install all
